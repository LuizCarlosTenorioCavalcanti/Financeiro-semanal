  INTEGRAÇÃO TÉCNICA
    • CSS escopado em #tab-vendas; variáveis --blue-* locais REMOVIDAS do
      módulo para herdar a paleta global e acompanhar troca de tema
      (testado nos 3 temas — cards, filtros e gráficos mudam de cor certo)
    • Chart.js próprio do arquivo-fonte (v4, embutido) foi DESCARTADO —
      o módulo usa o Chart.js v3.9.1 já carregado globalmente no <head>
      (mantém a regra técnica permanente #1 abaixo)
    • datalabels:{display:false} adicionado nos gráficos do módulo porque
      o Contratos já registra Chart.register(ChartDataLabels) globalmente

  BUGS ENCONTRADOS E CORRIGIDOS NESTA INTEGRAÇÃO
    1. Colisão de ids: Comissão e Vendas foram gerados a partir do mesmo
       template e usavam os MESMOS ids (cardVendaTotal, fEmpresa, chartLinha,
       treeRoot, btnLimpar etc. — 30 ids no total). getElementById sempre
       pega o primeiro do documento, então o Vendas escrevia dentro dos
       elementos ocultos do Comissão sem erro nenhum no console, e os
       próprios cards do Vendas ficavam travados em "—". Corrigido
       prefixando todos os ids do Vendas com "vnd".
    2. A correção acima, feita por regex de id estático, não pegou os ids
       montados por concatenação de string em JS (ex: 'cardVenda'+k) —
       gerou TypeError (setting innerHTML of null). Corrigido caçando cada
       ocorrência de getElementById(...) manualmente.
    Ver INSTRUCOES_ASSISTENTE.md, armadilha #9, para o procedimento
    completo a seguir da próxima vez que um módulo novo for integrado.


--------------------------------------------------------------------------------
  REGRAS TÉCNICAS PERMANENTES
--------------------------------------------------------------------------------
  1. Chart.js v3.9.1 APENAS — nunca carregar v4.x globalmente (se o
     arquivo-fonte do módulo novo trouxer seu próprio Chart.js embutido,
     descartar e reaproveitar o global)
  2. Ler arquivos com null-byte safety:
       open(...,'rb').read().replace(b'\x00',b'').decode('utf-8')
  3. CSS de cada aba escopado com #tab-X (função scope_css Python) — e sem
     redefinir variáveis --blue-* locais, para herdar o tema ativo
  4. Scripts de módulo em IIFE para isolar consts (const RAW, const DATA,
     const MESES_NM etc. não podem vazar pro escopo global)
  5. Lazy init com flag por aba (data-mounted / window._mount_NOME) —
     Chart.js falha em canvas com display:none
  6. Reflow (void el.offsetWidth) sempre no elemento animado, nunca no pai
  7. Edição do template __bundler: operar na string Python (após
     json.loads OU splicing direto com âncoras ASCII sem aspas/quebra de
     linha), recodificar com json.dumps(...)[1:-1] ou + replace '</' →
     '<\/' para manter a convenção de escaping do arquivo inteiro
  8. index.txt sempre em sincronia byte-a-byte com o v5.4.html (produção)
  9. Todo módulo novo precisa ter seus ids conferidos contra os ids já
     existentes no arquivo unificado antes da inserção (ver armadilha #9
     do INSTRUCOES_ASSISTENTE.md) — inclusive ids montados por
     concatenação de string em JS, não só os id="..." estáticos
